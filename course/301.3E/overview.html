03 / Evidence

Evidence has different strengths

What each tool can see,
and what it can’t.

Learners use three SPEED tools before deciding anything. None of them decides for them.

01Diagnose

Pattern counts on one task’s diff, F1 to F8. No tests, no model. A signal says look here. A zero says nothing matched. It has no rule for self-approval.

02Review

A clean-context reviewer reads the diff and declared files. Its verdict is an opinion. The stored approvals came from earlier rounds.

03Eval

Runs scenarios and records each test outcome. A passing test proves only what it asserts; a missing boundary row proves nothing about that boundary.

04The engineer

Checks a finding against the code and the spec, then gives it a disposition and an owner.

04 / Judgment

Human judgment / 15 minutes

Confirm. Refute.
Escalate.

Every item gets exactly one disposition, with evidence the learner checked and a named owner.

Confirm

A real defect,
ours to fix.

Name the file and line, the requirement it breaks, and the check that proves the fix.

Refute

A claim the evidence
does not support.

Quote the claim, then the lines that contradict it. Keep the claim in the evidence.

Escalate. A decision that belongs to someone else goes to them with its evidence, the stories it touches and the phase it blocks. The engineer does not choose the policy.

05 / Repair

Define, Plan and Verify, Run and Inspect

A repair others
can check.

The defect report is the repair’s specification. SPEED plans and runs the repair; the engineer checks it.

01Define

speed new defect <name> scaffolds a report. Fill in the requirement, the reproduction and a check that fails today.

02Plan

speed plan --defects … --feature adaptive-auth-repair turns reports into repair tasks.

03Verify

A reader that never saw the plan checks it against the reports.

04Run and inspect

The repair runs. Each defect’s own check must pass, the suite must pass, and no assertion may be removed to get there.

06 / Escalation

The decision no check can settle

Some questions belong
to their owners.

A card-testing block covers every small payment on a BIN. The traveler’s card shares the attack’s BIN. Every check is green.

What the engineer does

Name the conflict.

Show the block rule, the traveler’s card and the stories both features promise. Name the phase it blocks: enabling block mode.

Who decides

Both PMs and Risk.

Block scope and length were left open in 301.1E. Nobody in the room chooses them.

A precise escalation is a complete answer. A chosen policy is not.

07 / Close

Same fixture. Clear responsibility.

The end of the pathway.

Definition, delivery and validation of one change, by engineers who can say what each tool proved.

01Submit

The disposition list, defect reports, escalation note and repair evidence.

02Assessed on

Evidence the learner checked, correct dispositions, checkable reports, precise escalation, and a repair that keeps every assertion.

03Critical errors

Weakening a test to pass a repair, or choosing the block policy.

Before live delivery. Diagnose has been run on the snapshot. Review, eval, plan, verify and run have not been rehearsed with Claude as provider, and no cohort has taken the course.
